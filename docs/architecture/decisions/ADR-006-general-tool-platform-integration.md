# ADR-006：通用 Agent 工具平台整合

> 状态：已提议，待实施评审
> 日期：2026-10-15
> 相邻文档：[整站能力整合方案](../【技术方案】DIH整站能力整合方案.md) · [Monid 逆向报告](../【逆向报告】Monid网站UI与能力逆向.md) · [首页与目录视觉规范](../【设计规范】DIH首页与目录视觉规范.md)

## 背景

Data Intelligence Hub 现为纯数据采集平台。
产品入口是采集控制台，以 `/platforms` 为首页。

产品方向已确认扩展为通用 Agent 工具平台。
新增能力包括内容生成，后续包括通信、计算与存储。

现有结构无法直接承载新能力：

- `TaskRun.task_id` 是非空采集任务外键。
  `CollectionTask` 又绑定 `Source`。
  生成类结果无法在不扭曲语义的前提下写入。
- `BaseCollector` 返回 JSON 原始记录，不承载文件或媒体产物。
- 执行路径存在共享 demo workspace 回退，不适合对外执行。
- 进程内限流不是持久配额。

## 决策

采用**一个目录、两种入口、一个调用门、受控执行适配器**。

### 1. 单一目录

保留现有采集 catalog 作为采集事实源。
在其上提供统一只读投影，并合入受控生成工具描述。
不人工维护第二份重复能力清单。

### 2. 单一调用门

网页、REST 与 MCP 都经过同一服务。
该服务负责身份、项目授权、参数校验、幂等与用量控制。

### 3. 受控执行适配器

- 采集类沿用现有 Collector 与 `TaskRun`。
- 生成类使用新增适配器与产物契约。
- 不通过创建虚假 `Source` 或 `RawRecord` 包装生成结果。

### 4. 新增两个最小对象

- `ToolCall`：统一身份、幂等、分派、预算与后端引用。
- `Artifact`：生成类产物引用，含类型、大小、摘要与授权。

采集调用不复制运行状态。
其状态仍只由 `TaskRun` 拥有，`ToolCall` 只在查询时投影。

### 5. 单一前端承载

以 `apps/scraper-console` 承载公开区与授权区。
不新建第三套前端，不把内部 Web 同时改造上线。

## 备选方案与拒绝理由

| 备选 | 拒绝理由 |
|---|---|
| 把生成结果写入 `RawRecord` | 扭曲「记录数、去重、数据源、成功」语义 |
| 泛化 `TaskRun` 承载所有工具 | 图谱影响 HIGH（105 节点 / 23 文件），迁移风险高 |
| 整体移植 Monid 的 Deno 运行时 | 并存两套鉴权、任务状态与凭据管理 |
| 并列维护两套目录 | 两套真相会漂移 |
| 开放任意 URL 或 HTTP 方法执行 | 安全边界不可控 |

## 影响

正向：

- 业务用户与开发者共用同一契约与权限模型。
- 一次提交对应一个可追踪调用，不出现双重状态。
- 生成与采集各有正确语义。
- 旧采集链路与历史链接不受影响。

负向与成本：

- 新增两个对象与其迁移。
- 需要持久队列与租约，现有 scheduler 不足。
- 需要强制身份改造，涉及大量动态 `Depends` 引用。
- 双词族 token 与旧品牌值需要清理。

## 未决事项

- `TaskRun` 与 `ToolCall` 的关联接缝需逐符号 impact 评审。
- `get_auth_context` 的迁移需按路由逐项核验。
- 首个内容生成供应商选型。
- 邀请与项目授权的角色模型。

## 相关证据

- `TaskRun` 图谱影响：HIGH，105 节点，23 个直接引用文件。
- `get_auth_context` 图谱结果：UNKNOWN，但文本补证确认大量动态引用。
