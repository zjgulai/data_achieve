# 生产变更的隔离与串台防线

两台生产主机都运行大量其他 Docker 应用。生产 B 上有 86 个运行中的容器，分属 40 多个 Compose 项目。

本项目与它们共享一台宿主机和一个网关。本文规定隔离红线。本文同时给出验证方法。验证必须留下证据。

## 隔离红线

以下动作永远不做：

1. 不执行 `docker volume prune`、`docker system prune`、`docker network prune`。
2. 不删除或重建外部网络 `lighthouse_ai_video_net`。该网络服务 10 个以上域名。
3. 不重启、不重建共享网关 `ai_video_nginx`。只允许 `nginx -t` 与 `nginx -s reload`。
4. 只删除本项目自己的三个具名卷。
   - `data_achieve_scrapy_postgres_data`
   - `data_achieve_scrapy_export_data`
   - `data_achieve_scrapy_browser_data`
5. 不在宿主机绑定 80 或 443 端口。本项目全部使用 `expose`。
6. 不动任何非 `data_achieve_scrapy_` 前缀的容器。

## 为什么隔离成立

三条设计保证。

1. 容器名、卷名、Compose 项目名都带 `data_achieve_scrapy` 前缀。它们只与自身冲突。
2. Compose 文件无 host 端口绑定。对外只经共享网关。
3. edge 容器同时连接内部网络与 `lighthouse_ai_video_net`。它持有别名 `data_achieve_scrapy_proxy`。共享 Nginx 只按别名转发。

## 隔离性验证

变更前后各取一次快照。然后对比。

### 快照

```bash
docker ps --format '{{.Names}}\t{{.Status}}' | sort > /opt/backups/.../containers-before.txt
docker inspect ai_video_nginx --format '{{.State.StartedAt}} {{.RestartCount}}'
```

### 对比

```bash
diff <(grep -v data_achieve_scrapy containers-before.txt | cut -f1) \
     <(docker ps --format '{{.Names}}' | grep -v data_achieve_scrapy | sort)
```

通过标准：

1. 非 DIH 容器名集合零差异。
2. `ai_video_nginx` 的 StartedAt 与 RestartCount 与变更前逐位相同。

2026-10-11 生产 B 部署后的实测：非 DIH 容器零差异。`ai_video_nginx` 为 `2026-10-01T14:09:07.346558459Z` / 0，与基线相同。

### 坑点：对比两侧格式必须一致

2026-10-11 的一次对比出现假阳性。一侧是「名字+状态」，另一侧是「只有名字」。排序结果不同，diff 以为大量容器变动。

对比前必须确认两侧格式相同。

## 串台防线

串台指一环境的前端指向另一环境。本项目有两套环境。域名不同。

### 机制

前端地址在**构建时烧录**。console 与 web 读取 `NEXT_PUBLIC_API_URL`。该值来自构建参数 `SCRAPY_PUBLIC_URL`。

后果：

1. 每个环境的 `SCRAPY_PUBLIC_URL` 必须指向自己的域名。
2. 必须在 `build` 之前设好。构建后再改无效。
3. 改动域名必须重建镜像。

### 复核方法

构建后用产物复核。产物里只应出现本机域名：

```bash
docker exec data_achieve_scrapy_console sh -c \
  "grep -rhoE 'https://scrapy\.[a-z0-9.-]+' /app/.next/static | sort -u"
docker exec data_achieve_scrapy_web sh -c \
  "grep -rhoE 'https://scrapy\.[a-z0-9.-]+' /app/apps/web/.next/static | sort -u"
```

出现另一台机器的域名即为串台。必须重建镜像。

### 坑点：源码里的硬编码域名躲过构建参数

2026-10-11 生产 B 重建时抓到一处。console 的技能详情页把 `https://scrapy.luteos.com` 写死在三处展示字符串里。它们不跟随 `NEXT_PUBLIC_API_URL`。

修法：让字符串改用 `API_BASE_URL`。该常量读同一个环境变量。

新加展示地址时必须检查：

1. 地址来自 `API_BASE_URL` 或同类常量。
2. 复核命令的输出只有本机域名。
