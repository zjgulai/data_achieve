## A1. production-truth-probe

- 名称：`scripts/production_truth_probe.py`，并扩展 `scripts/check_dual_production_drift.sh`。
- 类型：只读探针脚本加发布账本写入钩子。
- 消除的坑：P2 导出 worker 从未启动；P3 审批默认值反向；P6 账本缺 schema 与 B 漂移；容器 running 但功能不工作。
- 触发：`deploy-p0.sh` 成功后自动；每日 09:00；发布验收；周复盘取数前。
- 步骤：
  1. 公网探针：A 与 B 的 `/api/health`，取 status、database、schema、schema_revision、schema_head。
  2. SSH 只读探针：`git rev-parse HEAD`；`docker compose ps`；`alembic current`；`meta.worker_heartbeat` 每角色最近心跳；`meta.ingest_job` 与 `abi.export_job` 的 queued 年龄；关键表行数。
  3. 比对：主机 HEAD 等于账本最新 commit；alembic_version 等于仓库 `alembic heads`；必需服务 running；心跳小于 180 秒；queued 超过 10 分钟为 0。
  4. 输出 JSON 到 `reports/ops/production-truth-YYYYMMDD.json`；账本追加 schema_revision、image、services、result。失败也记 failed。
- 验收：
  - PASS：所有检查通过，退出 0。A/B schema 不同只有在 `--allow-drift` 加冻结文件时才允许。
  - FAIL 夹具：删除 abi-export 服务后退出 1；伪造 10 分钟前心跳后退出 1；账本 commit 与 HEAD 不一致退出 1；无豁免的 A=068/B=056 在 --strict 下退出 1。
- 与现有资产关系：合并未提交的 `check_dual_production_drift.sh`（3 测试 PASS）与 `preflight-production.sh` 的只读探针；复用 `record_release.py` 写账本；替换 `production-acceptance` 技能里的硬编码数字。不新建第三套探针。
- 成本与风险：实现约 1.5 人日，维护 0.3 人日每月。风险是 SSH 权限被拒、B 迁移窗口、账本时间不能伪造。

## A2. file-integrity-repair

- 名称：`scripts/check_file_integrity.py --verify` 与 `--repair`。
- 类型：脚本加 hook 加 CI。
- 消除的坑：P1 尾洞与乱码头复发；证据文件 NUL；os.replace 后 755 变 644。
- 触发：每次 Write 或 Edit 后（PostToolUse）；pre-commit；CI；docker build 前；记忆目录扫描。
- 步骤：
  1. `--verify PATH`：st_size 等于 len(read_bytes)；原始块读取哈希等于 Python 读取哈希；NUL 为 0；严格 UTF-8 可解码；tracked 文件 mode 等于 git index。
  2. `--repair`：写临时 inode，fsync，os.replace，恢复 mode；再跑一次 verify；打印修复前后。
  3. `--edited` 扫描 `git status` 的已改与未跟踪文件；`--path` 扫描记忆目录。
  4. 接入 `/.githooks/pre-commit`、CI 与编辑后钩子。
- 验收：
  - PASS：正常文本、20 个二进制文件零误报；memory 目录扫描 0 失败。
  - FAIL 夹具：尾洞、乱码头、NUL、非法 UTF-8、755 变 644 各自 FAIL；repair 后同一夹具 PASS。
  - 修复后 `file`、ruff、读取三方一致。
- 与现有资产关系：扩展 `check_file_integrity.py`（工作树已有 --path，未提交）与 `.githooks/pre-commit`；SP-44 只覆盖 size 与 NUL，本项补垃圾头、UTF-8、mode、修复。
- 成本与风险：实现 0.5 至 1 人日，维护 0.1 人日每月。风险是二进制与大文件误报；repair 改变 mtime；必须保留原始哈希。

## A4. report-language-gate

- 名称：`scripts/check_report_language.py`。
- 类型：脚本加 CI 加导入钩子。
- 消除的坑：P9 报告无证据等级；P10 63 处术语回退；领导反馈看不懂；数字无分母或来源。
- 触发：导入或生成任何业务报告前；`tools/insight-reports/**/report.html` 提交；日报；CI 扫描报告包。
- 步骤：
  1. 禁用词表：样本不足、接近下限、外推、显著、p 值、置信区间、口径、归因、颗粒度、赋能、抓手、闭环、沉淀。引用块、术语表、解释性用法走 allowlist。输出 file:line。

  3. 每条结论有证据等级，或报告声明描述性归档。
  4. `--strict` 要求数字段带日期或 run_id。
- 验收：
  - PASS：63 词夹具 FAIL 且命中数为 63；当前 report.html 在 allowlist 下 PASS；正常报告零误报。

- 与现有资产关系：把未提交的 `report-review` skill 第二、三、五步变成机器检查；补 `voc_pipeline/voc/validate_report.py` 只覆盖 12 条禁写结论的空白；在 `import_insight_report.py`、`voc_pipeline/run.sh`、`daily-report.sh` 调用。
- 成本与风险：实现 1 人日，维护 0.2 人日每月。风险是术语误报与 allowlist 过宽；先对当前报告跑基线，再收紧。

## A6. daily-report-health

- 名称：`scripts/check_daily_report_health.sh`，并继续加固 `scripts/daily-report.sh`。
- 类型：脚本加定时任务。
- 消除的坑：P11 11-01 空目录；同日三版；21:07 截断；headless 无提交权限；目录双轨。
- 触发：每日 22:15 之后（10-31 的 21:07 运行到 21:45，耗时 38 分钟）；或读完成标记；周复盘前；手工补跑后。
- 步骤：
  1. 检查 `reports/achievements-YYYYMMDD/Source-项目成果总结-YYYYMMDD.md` 与 `.html` 存在且大于 0 字节；11-01 允许 `MISSING.md` 的 `known_gap`。
  2. 用 `grep '^RUN_STATUS=' | tail -1` 读状态。脚本先写 `RUN_STATUS`，再写 `end`，不能取最后一行。
  3. 检查 `launchctl print` 的 runs 与 last exit；检查重复报告文件；检查 MD 与 HTML 的 KPI 与 digest 配对。
  4. 缺失时退出 1，并通过数说机器人发飞书私信给 owner；发送失败也退出 1。
  5. 本机没有 `flock` 与 `timeout`。用 `mkdir` 原子锁或 `scripts/lib` 的 `run_with_timeout`；加 `--date` 补跑、T-1 窗口或 cutoff 标注；plist 入仓并提供 install 脚本。
  6. 增加外部 dead-man：生产 cron 或 GitHub Actions scheduled job 检查心跳文件；本机休眠时本机检查器也不会运行。
- 验收：
  - PASS：模拟缺失文件退出 1 且告警；`--date 20261101` 产出 `MISSING.md` 或非空报告；两个并发运行第二个不覆盖；下次定时 `RUN_STATUS=success`。
  - FAIL：日志无 RUN_STATUS、目录为空且无 MISSING.md、commit 缺失、MD 与 HTML 数字不一致，各退出 1。
- 与现有资产关系：扩展未提交的 `daily-report.sh` 加固（非空、脚本内提交、RUN_STATUS）与 launchd plist；与 A4 串联，报告先过语言闸门再提交。
- 成本与风险：实现 0.5 人日，维护 0.05 人日每月。风险是本机休眠、headless 权限、补跑内容不完整；补跑必须标数据截止。

## 7. 2026-11-02 对抗复核修正

复核发现以下方案会重复造轮子或不可执行。执行以本节为准。

### A1 production-truth-probe

不新建 `scripts/production_truth_probe.py`。现有四套探针已经覆盖大部分能力：

- `scripts/record_release.py` 的 probe：SSH 只读采集 commit、branch、image、container。
- `scripts/check_dual_production_drift.sh`：A/B health 与 schema。
- `scripts/preflight-production.sh`：A 的 HEAD、edge、health、密钥格式。
- `apps/api/src/data_intelligence_hub/maintenance/prod_health_check.py`：A 的 10 分钟 cron 与飞书告警。

改法：给 `record_release.py` 增加 `alembic_version`、`services`、`worker_heartbeat`、`queue_age`；给 drift 脚本增加 host HEAD 对账本与 `production_scope.json`；给 `prod_health_check.py` 增加 worker/queue 检查。删除新脚本名。

### A2 file-integrity-repair

- `--verify` 只报告；`--repair` 只处理可恢复的尾洞/截断，按读取长度截断并恢复 mode。
- 非法 UTF-8 与垃圾头标记 `quarantine`，要求从 git/备份恢复；tracked 源码默认不自动 repair。
- pre-commit 不自动 repair，避免掩盖缺陷。

### A3 security-floor-test

- 不新建 `test_security_floor.py` 复制现有 ABI 测试。扩展 `test_abi_export_approval_default.py` 与 `test_abi_pii_downgrade.py`。
- 这些测试在 `tests/postgres_abi/`，CI 只跑 `tests/unit`，且缺 `TEST_DATABASE_URL` 时 skip。必须新增 ABI Postgres CI job，或写成明确的本地 gate；否则测试永远不跑。
- `pii_class` 行为必须先拍板：`extra="forbid"` 或写入 `field_policy`。验收不能写「422 或写入」两分支都算过。

### A4 report-language-gate

- 不新建第四个校验器。仓库已有 `tools/insight-report/validate.py`、`tools/insight-report/ir_impl/validate.py`（两者字节相同）、`voc_pipeline/voc/validate_report.py`。
- 先删除 `ir_impl/validate.py` 重复副本；把白话词表与分母规则并入现有 validator，或抽一个共享 catalog。
- 若保留 CLI，只做 dispatcher。一个词表、一个 owner、一个 allowlist。

### A6 daily-report-health

- 本机没有 `flock` 与 `timeout`；用 `mkdir` 原子锁或 `scripts/lib` 的 `run_with_timeout`。
- 检查时间放在 22:15 之后，或读完成标记；不要固定在 21:30。
- `RUN_STATUS` 不是日志最后一行；用 `grep '^RUN_STATUS=' | tail -1`。
- 本机检查器无法发现「launchd 从未运行」；增加生产 cron 或 GitHub Actions 的外部 dead-man。
