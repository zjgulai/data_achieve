## 构建镜像源

生产 B 在腾讯云国内区，直连上游包源很慢，构建镜像会反复读超时。2026-10-11 实测：

| 上游 | 直连速度 |
|---|---|
| `pypi.org` / `files.pythonhosted.org` | 约 23 KB/s（18MB 的 wheel 90 秒只下 2MB） |
| `registry.npmjs.org` | 约 220 KB/s |
| `deb.debian.org` | 约 158 KB/s |

生产 B 的 `.env.production` 因此固定四个构建镜像源键。这四个键只影响构建，不影响运行：

| 键 | 值 | 覆盖 |
|---|---|---|
| `SCRAPY_PIP_INDEX_URL` | `https://mirrors.cloud.tencent.com/pypi/simple/` | pip 与 uv |
| `SCRAPY_NPM_REGISTRY` | `https://registry.npmmirror.com` | npm、pnpm 与 corepack |
| `SCRAPY_DEBIAN_MIRROR` | `mirrors.cloud.tencent.com` | apt（playwright `--with-deps`） |
| `SCRAPY_PLAYWRIGHT_DOWNLOAD_HOST` | `https://cdn.npmmirror.com/binaries/playwright` | Chromium 浏览器下载 |

三个约束必须同时满足，改值前先读：

1. **主机名要在构建容器里可解析。** `mirrors.tencentyun.com` 只在内网 DNS（宿主机的 systemd-resolved）下可解析，构建容器里报 ENOTFOUND；`mirrors.cloud.tencent.com`、`registry.npmmirror.com`、`cdn.npmmirror.com` 在容器内正常。
2. **`SCRAPY_NPM_REGISTRY` 不能以 `/` 结尾。** corepack 按 `<registry>/<包>/<版本>` 拼地址，尾斜杠会拼出双斜杠，npmmirror 对 `//pnpm/...` 返回 404。
3. **`SCRAPY_PIP_INDEX_URL` 必须以 `/simple/` 结尾。** api 镜像构建时按这个后缀推导文件主机（去掉后作前缀）改写 `uv.lock`：`uv sync --frozen` 只认锁文件里的绝对地址，只设索引变量不生效，会直连 `files.pythonhosted.org`（实测 26-46 KB/s）。改写只换主机名，包路径与 sha256 不变，uv 仍逐包校验。索引是官方源时整段跳过。

`configs/deploy/scrapy/docker-compose.yml` 把四个键传给 api、web、console、spiderfoot 四个服务的 `build.args`。Dockerfile 的默认值与官方源一致。生产 A 不设这四个键，因此仍走官方源，行为与本次改动前相同。

`SCRAPY_PLAYWRIGHT_DOWNLOAD_HOST` 必须指向能提供 `builds/cft/<版本>/linux64/chrome-linux64.zip` 的镜像。playwright 1.62 起，Linux x64 的 Chromium 改为 Chrome for Testing 布局，不再是 `builds/chromium/<revision>/`。

## 访问链路

```text
Browser
  → 主机 443 / ai_video_nginx
  → lighthouse_ai_video_net
  → data_achieve_scrapy_proxy:8080 / data_achieve_scrapy_edge
  → Console 或 API
```

两套环境的结构相同。共享 `ai_video_nginx` 在 80/443 终止 TLS，其 upstream 为 `data_achieve_scrapy`，指向 `data_achieve_scrapy_proxy:8080`。域名到 upstream 的映射由各主机的 `ai_video_nginx` 配置决定。当前链路不经过旧内网服务器或 SSH 反向隧道。

> `data_achieve_scrapy_proxy` 不是独立容器，而是 **edge 容器在 `lighthouse_ai_video_net` 上的网络别名**。

## 采集请求的超时分层

一次 `POST /api/quick-collect` 要穿过四层预算，**取最先到期的那一层**：

| 层 | 位置 | 默认 | 说明 |
|---|---|---|---|
| 共享 nginx | 主机 `/opt/ai-video/deploy/lighthouse/nginx.conf` | `/api/quick-collect` **1800s**，其余 300s | 精确匹配块；改完要 `docker exec ai_video_nginx nginx -s reload` |
| edge nginx | `configs/deploy/scrapy/edge-nginx.conf` | 同上 | bind mount：**git 替换文件会换 inode，必须重建 edge 容器**，只 reload 不生效 |
| 应用守卫 | `collector_service` | task config 的 `run_timeout_seconds`；缺省见下，上限 1800s | 校验器对这些采集器是透传，所以调用方可在 `params` 里传 `run_timeout_seconds` |
| 采集器子进程 | `OSINT_PROC_TIMEOUT` / `SPIDERFOOT_TIMEOUT` | 800 / 1500 | 必须留在应用守卫之内，否则拿不到结构化错误 |

长任务还有一条 MCP 路径：`/mcp/` 与 `POST /mcp` 同样是 3600s，适合超过 30 分钟的采集。

应用守卫的缺省值按端点分档（`collector_service.SLOW_ENDPOINT_TIMEOUT_SECONDS`）：

| 端点 | 缺省守卫 | 实测 |
|---|---|---|
| `aliens_eye_advanced` | 1700s | A 391s / 5032 条；B 慢 3 倍以上，1200s 不够 |
| `aliens_eye_selfcheck`、`aliens_eye_recurse` | 1200s | selfcheck A 136s / B 444s；recurse A 252s |
| `spiderfoot_email_osint`、`spiderfoot_subdomain_enum`、`spiderfoot_attack_surface` | 1200s | A 均 <300s；B 超 300s |
| 其余全部端点 | 300s | — |

取值规则：**高于实测耗时、低于 nginx 上限 1800s（保证由 API 作答）、低于采集器子进程预算
（1600s / 1500s，保证跑飞的扫描以采集器自己的结构化错误收场）**。调整任一端点前先按这条规则核算。

> 超长采集不要指望单个同步 HTTP 响应：服务端会继续跑完，但客户端连接可能被更上游的空闲
> 超时重置（实测约 575s）。这类任务应走 MCP，或轮询 `GET /api/tasks/runs`
> 配合 `GET /api/raw-records?task_run_id=` 取结果。

前置地址在 Console 和 Web 镜像**构建时烧录**（`NEXT_PUBLIC_API_URL`，取自 `SCRAPY_PUBLIC_URL`）。每个环境的 `SCRAPY_PUBLIC_URL` 必须指向自己的域名，且必须在 `build` 之前设好。改动域名必须重建 Console 和 Web 镜像。

## 网络与数据卷

| 类型 | 名称 | 用途 |
|---|---|---|
| 内部网络 | `data_achieve_scrapy_internal` | 项目容器互联 |
| 外部网络 | `lighthouse_ai_video_net` | 共享网关访问 edge |
| PostgreSQL volume | `data_achieve_scrapy_postgres_data` | 数据库持久化 |
| Export volume | `data_achieve_scrapy_export_data` | 数据集导出 |
| Browser volume | `data_achieve_scrapy_browser_data` | 浏览器采集状态 |

不得删除或重建 `lighthouse_ai_video_net`。生产 secrets 只存放于 `.env.production`，不得提交 Git。

生产 Compose 无 host 端口绑定，全部使用 `expose`。因此同主机上的其他 Docker 应用不受影响，但同主机也不能再跑第二套。

`.env.production` 位于项目目录，不在 Compose 目录。所有 Compose 命令必须显式传入 `--env-file /opt/data-achieve-scrapy/.env.production`，否则 secrets 解析为空。

预期结果：

- health 返回 `status=ok`、`database=connected`、`schema=current`。
- 平台包返回 `70 / 270 / 242`。
- `/platforms` 返回 `200`。
- 未携带 Token 的 `/mcp/` 返回 `401`。

前端烧录地址复核（防串台）。Console 与 Web 的产物里只应出现本机域名：

```bash
docker exec data_achieve_scrapy_console sh -c \
  "grep -rhoE 'https://scrapy\.[a-z0-9.-]+' /app/.next/static | sort -u"
docker exec data_achieve_scrapy_web sh -c \
  "grep -rhoE 'https://scrapy\.[a-z0-9.-]+' /app/apps/web/.next/static | sort -u"
```

出现另一台机器的域名即为串台，必须重建镜像。2026-10-11 生产 B 重建时，Console 的技能详情页把 `https://scrapy.luteos.com` 硬编码在 MCP 端点与 curl 示例里，被这条检查抓出（已改为跟随 `API_BASE_URL`）。
