# DIH 整站能力整合方案

> 状态：范围已确认，尚未进入实施。
> 依据：[Monid 逆向报告](./【逆向报告】Monid网站UI与能力逆向.md) · [首页与目录视觉规范](./【设计规范】DIH首页与目录视觉规范.md) · [能力总账](./【能力总账】DIH-平台能力现状与维护手册.md)
> 产品代码实施、提交与部署均未授权。

## 1. 方案摘要

**建设一个通用工具平台，不再建设第二套采集平台。**

产品结构：

- 一个工具目录，同时服务业务用户与开发者。
- 两种入口：网页结构化任务、API / MCP / Skill。
- 一个调用门，统一身份、项目授权、参数校验与用量控制。
- 多个受控适配器：保留采集内核，首批增加内容生成。
- 一个运行视图，展示状态、日志、用量与产物。
- 一套品牌与组件规范，覆盖公开区与授权区。

整站改造不等于同时上线所有工具类别。
通信、计算与存储属于后续扩展。

## 1.1 术语与命名

引入通用平台后，「工具」「能力」「端点」「平台包」必须定名。
否则目录、详情和 API 会出现三套叫法。

| 术语 | 含义 | 不要用 |
|---|---|---|
| 工具 | 用户可调用的最小单元，对应一个 `tool_id` | capability、function |
| 能力视图 | 工具在某个平台分类下的展示条目 | 端点（易混） |
| 端点 | 上游服务的实际接口，属于实现细节 | 工具 |
| 平台包 | 平台维度的 Skill 打包单元，沿用现有定义 | 工具包、能力包 |
| 调用 | 一次工具执行，对应一个 `ToolCall` | 任务、作业 |
| 采集任务 | 现有 `CollectionTask`，仅指采集类 | 调用 |
| 运行 | 一次调用的执行记录，采集类由 `TaskRun` 承载 | 任务 |
| 产物 | 调用的输出资产，对应 `Artifact` | 结果文件、输出物 |
| 数据集 | 现有 `Dataset` 定义，沿用 | 数据资产 |
| 抽屉 | 右侧滑出面板 | 弹窗、侧边栏 |
| 对话框 | 覆盖式模态框 | 弹窗 |

术语表需同步写入 [写作标准](../standards/writing-standard-ste.md)。
在新词定型前，文档只用本表左列。

## 2. 已确认范围

| 维度 | 已确认 |
|---|---|
| 用户 | 业务用户与开发者 / Agent 同等优先 |
| 网站范围 | 官网、目录、接入页、整个控制台 |
| 平台定位 | 通用 Agent 工具平台 |
| 业务交互 | 结构化任务优先，对话辅助 |
| 首发开放 | 目录公开；执行限受邀用户 |
| 费用模式 | 平台承担供应商成本；首发不做自助支付 |
| 供应商凭据 | 管理员统一配置，按项目授权使用 |
| 新增类别 | 首批文本与图片生成；视频与音频随后 |
| Agent 执行 | 项目白名单与额度内预授权；超限阻止 |
| 品牌 | 保留暖纸底、玫瑰行动色与证据优先风格 |

## 3. 奥卡姆剃刀：首期不做

- 不整体移植 Monid 的 Deno 运行时。
- 不重写现有 Collector、TaskRun 与数据集链路。
- 不将生成结果包装成假 RawRecord。
- 不建设第三套前端。
- 不并列维护两套能力目录真相。
- 不开放任意 URL、任意 HTTP 方法或上传插件执行。
- 不建设通用可视化工作流引擎。
- 不依赖当前 fixture 工作流完成真实任务。
- 不做支付、钱包、订阅、佣金或供应商入驻市场。
- 不承诺独立 SDK 或 CLI，先用现有 REST / MCP / Skill。
- 不默认增加对话 Agent 或模型路由系统。
- 不复制参考站品牌图、字体依赖与装饰动画。
- 不因媒体生成同时建设编辑器、素材商城或公开分享社区。

首期新增对象只服务实际缺口：通用调用、生成产物、持久用量控制。

## 4. 全站信息架构

### 4.1 公开区

| 路由 | 内容 | 主要动作 |
|---|---|---|
| `/` | 首屏主张、能力概览、三步流程、接入方式、FAQ | 在网页中使用 / 接入 Agent |
| `/tools` | 搜索、分类、可用状态筛选、能力行 | 查看能力 |
| `/tools/[toolId]` | 说明、输入、输出、示例、限制、最近核验 | 创建任务 / 查看接入 |
| `/connect` | REST、MCP、Skill 分页签与示例 | 接入 |
| `/docs` | 复用 Playbook 与采集文档 | 查阅 |

公共目录只暴露安全元数据。
缺失密钥名称、内部主机名与完整上游错误留在管理员诊断。

### 4.2 授权工作区

主导航保持少量稳定领域：

- 工具：当前项目可用的能力。
- 项目：成员、工具准入、限额与默认上下文。
- 任务：保存配置、创建任务、重跑。
- 运行：全部调用的状态、错误与用量。
- 资产：数据集与生成产物，按类型展示。
- 接入：平台访问凭据与配置示例。

管理员设置独立：

- 邀请用户与项目授权。
- 供应商凭据与工具启停。
- 核验记录、额度调整与异常用量。

### 4.3 页面承载与旧链接

- 以 `apps/scraper-console` 承载公开区与授权区。
- 保留既有标识与链接，不丢参数跳转。
- 内部 `apps/web` 不同时改造上线，仅按需复用界面模式。

**前置事实（2026-10-15 核验）**：现有 console 页面**不读取任何 URL 查询参数**。
筛选与分页全部是组件内 `useState`，`searchParams` / `useSearchParams` /
`location.search` 在 console 源码中零命中。

这改变了下表的语义：
「保留筛选参数」不是保持不变，而是**新增 URL 状态承载**。
要让筛选条件可分享、可返回，须先实现 URL 参数读写。
工作量按新增功能估，不按兼容估。

现有控制台路由与新 IA 的对照：

| 现有路由 | 新位置 | 处理方式 |
|---|---|---|
| `/` | `/` | 由重定向到 `/platforms` 改为公开首页 |
| `/platforms` | `/tools` | 重定向；筛选状态需新增 URL 承载 |
| `/skills` | `/tools` | 重定向；筛选状态需新增 URL 承载 |
| `/skills/[platformId]` | `/tools/[toolId]` | 重定向，保留路径参数 |
| `/collector-docs` | `/docs` | 重定向 |
| `/projects` | `/projects` | 保持路径 |
| `/projects/[id]` | `/projects/[id]` | 保持路径 |
| `/tasks` | `/tasks` | 保持路径 |
| `/runs` | `/runs` | 保持路径 |
| `/collect/[run_id]` | `/runs/[runId]` | 重定向，保留路径参数；段名风格由 snake_case 改为 camelCase |
| `/datasets` | `/assets` | 重定向；筛选状态需新增 URL 承载 |
| `/raw-records` | `/assets/records` | 重定向；查询条件需新增 URL 承载 |
| `/dashboard` | `/dashboard` | 保持路径，内容按新 IA 重排 |
| `/settings/account` | `/settings/account` | 保持路径；现为占位空页，需实现 |
| `/settings/credentials` | `/settings/credentials` | 保持路径，纳入管理员设置 |
| 新增 | `/connect` | 新增接入页 |
| 新增 | `/tools/[toolId]` | 新增工具详情 |
| 新增 | `/settings/providers` | 新增供应商凭据管理 |
| 新增 | `/settings/members` | 新增用户与授权管理 |

已核验：表中 15 条现有路由在 console 中全部真实存在，无遗漏无多余。
新目标路径与现有路由零冲突，也不撞 API 前缀或 FastAPI 文档路径。

**注意 `apps/web` 是独立路由集**，独有 20+ 路由，
且与 console 共享 5 个同名路径（`/dashboard`、`/datasets`、`/projects`、
`/raw-records`、`/tasks`）。做迁移时勿把 web 路由当成 console 的。

重定向表在 P0 冻结，逐条写测试。
不保留无参数兜底的丢参跳转。

## 5. 三条首期主流程

### 5.1 业务用户：结构化采集

```text
选择项目与工具
  → 填写参数
  → 查看输入摘要、限制与成本上限
  → 确认执行
  → 查询状态与日志
  → 预览原始结果
  → 如需数据集，显式保存版本后导出
```

不宣称采集完成自动产生 DatasetVersion。
重跑成功但新增零条记录，应说明去重或空结果原因。

### 5.2 业务用户：内容生成

```text
选择生成工具
  → 填写结构化提示、输入素材与输出规格
  → 查看项目、供应商与成本上限
  → 执行并取得稳定调用 ID
  → 查看排队、执行、失败或完成状态
  → 预览、下载产物，或复制为新任务参数
```

每类先接一个经验收的供应商，不同时建设自动比价路由。

### 5.3 开发者 / Agent

```text
发现工具并获取稳定 ID
  → 查看输入输出契约
  → 使用项目绑定的平台访问凭据
  → 提交调用及幂等键
  → 获得与网页相同的调用 ID
  → 查询结果与产物
```

## 6. 最小后端整合

### 6.1 一个规范化目录

保留现有 catalog 作为采集事实源。
在其上提供统一只读投影，并合入受控生成工具描述。
不让人工维护第二份重复能力清单。

最小工具描述字段：

- 稳定 `tool_id` 与契约版本。
- 业务名称、说明、类别、提供商。
- 输入 schema、输出类型、示例与限制。
- 风险类别：读取、生成、外发、计算。
- 可用性证据及核验时间。
- 是否支持同步或异步、是否可取消。
- 成本计量方式与可执行上限。

现有 required_params / optional_params 不等于完整类型 schema。
先为实际公开执行的端点补类型、默认值、范围与验证器。

### 6.2 一个调用门

网页、REST 与 MCP 都经过同一服务：

1. 强制身份与项目授权。
2. 工具准入与契约版本检查。
3. 参数验证及资源所有权检查。
4. 幂等性检查。
5. 预算上限与并发限制。
6. 成本预留或审批。
7. 持久记录调用意图。
8. 分派到受控适配器。

调用 ID、输入摘要、项目、工具版本与成本策略在受理后固定。
同一幂等键配不同参数必须返回冲突。
未配置鉴权的 MCP 或旧 quick-collect 不能作为旁路。

### 6.3 不制造双重运行状态

现有 `TaskRun.task_id` 是非空采集任务外键。
其图谱影响为 HIGH，不直接泛化为所有工具运行。

最小方案：

- 新建轻量 `ToolCall`：统一身份、幂等、分派、预算与后端引用。
- 采集调用：状态仍只由既有 TaskRun 拥有。ToolCall 关联其 ID，查询时投影，不复制 status。
- 生成调用：ToolCall 自己拥有生成状态、供应商任务 ID 与结果引用，不创建虚假 CollectionTask 或 Source。
- 关联 TaskRun 的动作在其创建事务内完成，必须早于真实供应商调用。
- 分派中的调用有持久状态与恢复规则；交接后不得由两个执行器同时写运行状态。
- 旧 TaskRun 历史链接继续可读。

统一的是产品契约，不是强迫所有执行器使用同一数据库模型。

### 6.4 一个产物入口，不改坏数据集

新增最小 Artifact 契约：

- 所属项目与调用 ID。
- 产物类型：文本或受控文件引用。
- MIME、大小、内容摘要与创建时间。
- 原始来源与生成参数摘要。
- 访问授权、保留期与下载方式。

采集结果仍为 RawRecord / DatasetVersion。
资产页聚合不同类型，不复制一份数据集。
生成产物明确标注「生成内容」，不等同事实证据。
引用链接检查所有权与来源。
不在浏览器暴露供应商密钥或永久私有地址。
未知格式不以可执行 HTML/SVG 直接嵌入页面。

### 6.5 有界异步

长任务必须先持久受理，再返回调用 ID。
不把浏览器请求连接当作任务生命周期。

首期在现有技术栈内增加受控 worker。
优先使用现有数据库的持久队列与租约，不先引入新编排平台。

实现必须覆盖：

- 原子领取、租约与心跳。
- 超时与重启恢复。
- 供应商任务 ID 保存。
- 幂等提交与轮询。
- 原始输出与产物持久化。
- 未知结果的人工对账。

只有供应商支持幂等或可查询已有任务时才自动重试提交。
请求可能已被接受但状态未知时，进入待确认状态。
取消请求不等于上游已停止，界面必须区分。

## 7. 认证、凭据与成本

### 7.1 受邀执行不是匿名演示

新调用门使用强制身份，不复用未登录 demo-owner 回退。
所有执行、产物查询、下载与用量接口做项目授权。
工作区身份不能只由调用者提交的 project_id 决定。
旧执行接口也须接入同一策略，或仅留在严格隔离的演示环境。

### 7.2 平台凭据

- 管理员统一管理供应商密钥。
- 项目获得工具准入，不获得原始密钥。
- 按工具与项目选择凭据，记录凭据版本而非密钥本身。
- 日志、错误、浏览器响应与 Skill 包不包含秘密。

### 7.3 额度不是钱包

- 管理员设置工具白名单、单次上限、每日额度与并发上限。
- 受邀项目默认不启用收费执行，直到管理员明确授额。
- 网页每次执行展示摘要；Agent 在已授权额度内调用。
- 超限或无法可靠确定成本上界时阻止执行。

持久用量流程：预留 → 执行 → 对账 → 结算或释放未用额度。
使用原子事务避免并发超额。
未取得可靠实际用量时保留估算与待对账状态。

不承诺「失败一定免费」。
只有已证实未执行或可确认未消费的部分才释放预留。
未来外发与高风险工具另设逐次确认。

## 8. 组件方案

只保留必要组件角色：

| 角色 | 用途 |
|---|---|
| AppShell | 公开区与授权区共享品牌，导航按区分离 |
| ToolRow | 目录中的一行能力 |
| ToolDetails | 业务说明与高级参数分层 |
| ParameterForm | 由已验证 schema 驱动 |
| ActionReview | 项目、输入摘要、成本上限与确认 |
| RunStatus | 状态、原因、下一步与时间 |
| ArtifactPreview | 文本、表格与媒体的类型化展示 |
| EvidenceDrawer | 核验来源、时间、限制与诊断 |
| StateBlock | 空、加载、错误、无权限四态 |

Console 现有组件优先演进。
内部 Web 模式只按需迁移，不新建平行组件库。

交互标准见 [首页与目录视觉规范](./【设计规范】DIH首页与目录视觉规范.md)。

## 9. 分期与验收

### P0 契约与边界

产出：规范化目录、ID 映射、参数 schema、权限与用量策略、旧路由清单。

验收：

- 明确目录视图数与唯一端点计数。
- 每个首发工具有输入、输出、限制与核验记录。
- 匿名只能读取公共元数据。
- 旧执行入口不存在绕过新权限的路径。

### P1 整站框架与发现

产出：首页、统一目录、工具详情、接入页、工作区壳层与移动导航。

验收：

- 两类用户都有清晰入口。
- 搜索、筛选与详情返回保留上下文。
- 旧项目、任务与数据集链接仍可用。
- 不展示不可执行功能的误导按钮。
- 桌面、移动、键盘与空错误状态通过检查。

### P2 受邀执行与采集兼容

产出：统一调用门、项目权限、凭据引用、幂等与持久用量。

验收：

- 网页与 MCP / API 读取同一调用状态。
- 重复提交不重复触发 Provider。
- 不能越权读取其他项目运行或产物。
- 旧 collect 保持采集语义。
- 采集结果、日志与数据集导出无回归。

### P3 内容生成闭环

产出：首批受控生成适配器、异步运行与产物预览下载。

验收：

- 受邀用户能完成创建、确认、执行、查询与下载。
- Worker 重启后任务可恢复或进入明确待确认状态。
- 实际用量与估算区分，未知费用不假装为零。
- 空结果、Provider 错误、超时与取消各自可解释。
- 供应商真实调用验收另行取得授权与预算。

### P4 整站收尾

覆盖项目、任务、运行、资产、接入与管理员设置。
逐页替换旧品牌值与割裂入口。
完成旧链接兼容、文档与回归清单。

## 10. 成功标准

1. 用户可从目录找到真实可用工具。
2. 业务用户无需复制代码即可完成结构化任务。
3. Agent 使用相同契约与权限调用工具。
4. 一次提交对应一个可追踪调用，不出现双重状态。
5. 有效结果、空结果与失败不会混淆。
6. 平台凭据不泄露，项目权限不可绕过。
7. 费用有上限与记录，不依赖内存计数。
8. 生成产物与采集数据有各自正确语义。
9. 旧采集能力与历史链接不因重设计失效。
10. 全站保持 DIH 品牌。

## 11. 实施前风险

`TaskRun` 图谱影响为 HIGH：105 个影响节点，23 个直接引用文件。
本方案绕开对其语义与外键的大规模改造。
必要的关联接缝仍须逐符号 impact、测试与迁移评审。

`get_auth_context` 图谱结果为 UNKNOWN。
