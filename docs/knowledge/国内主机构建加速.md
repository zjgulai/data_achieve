# 国内主机构建加速

生产 B 在腾讯云国内区。它直连上游包源很慢。构建镜像会反复读超时。

本文记录完整方案。镜像源的当前值与三个约束见 [生产环境基线](../【运维手册】生产环境基线.md) 的「构建镜像源」一节。相关技能见 `.claude/skills/production/production-image-build/`。

## 问题

2026-10-11 实测直连速度：

| 上游 | 速度 |
|---|---|
| `pypi.org` / `files.pythonhosted.org` | 约 23 KB/s |
| `registry.npmjs.org` | 约 220 KB/s |
| `deb.debian.org` | 约 158 KB/s |

api 镜像依赖约 200 个 Python 包。它还要下载 Chromium，约 190 MiB。直连不能完成构建。

## 方案

方案分四层。每层换掉一个慢源。

1. pip 与 uv：索引换为腾讯云 PyPI 镜像。
2. apt：Debian 源换为腾讯云镜像。
3. npm 与 pnpm：registry 换为 npmmirror。
4. Playwright：浏览器下载主机换为 npmmirror。

四个键定义在 `.env.production`。compose 把它们传入 `build.args`。Dockerfile 的默认值是官方源。生产 A 不设这些键，行为与改动前相同。

相关文件：

| 文件 | 作用 |
|---|---|
| `configs/deploy/scrapy/docker-compose.yml` | 四个服务的 `build.args` |
| `apps/api/Dockerfile` | pip、uv、apt、Playwright，另含锁文件改写 |
| `apps/web/Dockerfile` | npm 与 corepack |
| `apps/scraper-console/Dockerfile` | npm |
| `configs/bridges/spiderfoot-bridge/Dockerfile` | pip |

## 为什么需要改写 uv.lock

`uv sync --frozen` 只按 `uv.lock` 下载。锁文件里每个包都带绝对地址。只设 `UV_DEFAULT_INDEX` 不生效。

2026-10-11 实测：设了索引变量后，请求仍全部发往 `files.pythonhosted.org`。速率只有 26-46 KB/s。

修法：api 的 Dockerfile 在构建时改写锁文件主机名。

```dockerfile
RUN if [ "$PIP_INDEX_URL" != "https://pypi.org/simple" ]; then \
      sed -i "s|https://files.pythonhosted.org|${PIP_INDEX_URL%/simple/}|g; s|https://pypi.org/simple|${PIP_INDEX_URL}|g" uv.lock; \
    fi
```

改写只换主机名。包路径与 sha256 不变。uv 仍逐包校验哈希。安全性不降低。

因此 `SCRAPY_PIP_INDEX_URL` 必须以 `/simple/` 结尾。文件主机由它去掉这个后缀得到。

## 验证方法

换源后必须验证两件事，再开始构建。

1. 镜像源能返回同一个文件。取锁文件里一个 wheel 的地址，替换主机名后下载。
2. sha256 与锁文件一致。

```bash
URL='<替换主机名后的 wheel 地址>'
curl -fsSI --max-time 20 "$URL"
curl -fsS --max-time 30 "$URL" | shasum -a 256
```

第三次验证是构建耗时。修复前 api 构建停滞数小时。修复后主步骤 337 秒。

## 维护场景

### 升级 Playwright 后路径变化

playwright 1.62 起，Linux x64 使用 Chrome for Testing 布局。下载路径为 `builds/cft/<版本>/linux64/chrome-linux64.zip`。

api 镜像不固定 playwright 版本（`uv pip install playwright` 无版本号）。升级后浏览器版本会变化。下载主机必须能提供新路径。

`SCRAPY_PLAYWRIGHT_DOWNLOAD_HOST` 替换整个镜像前缀。不要保留官方路径片段。

### 更换镜像源

换源前先跑诊断。顺序如下：

1. 在构建容器里解析候选主机。宿主机的 DNS 结果不可信。
2. 下载一个小文件测速。

2026-10-11 的教训：`mirrors.tencentyun.com` 在宿主机可解析。它在构建容器里报 ENOTFOUND。必须选容器内可解析的主机。

### corepack 的双斜杠

corepack 按 `<registry>/<包>/<版本>` 拼地址。registry 带尾斜杠会拼出双斜杠。npmmirror 对 `//pnpm/...` 返回 404。

因此 `SCRAPY_NPM_REGISTRY` 不能以 `/` 结尾。

## 坑点表

| 坑点 | 现象 | 规避 |
|---|---|---|
| 宿主机 DNS 与容器 DNS 不同 | 容器内 ENOTFOUND | 换源前在容器内验证解析 |
| 锁文件带绝对地址 | 换索引变量无效 | 构建时改写锁文件 |
| corepack 尾斜杠 | 双斜杠 404 | registry 不带尾斜杠 |
| Playwright 路径变化 | 下载 400 | 按版本核对 CFT 路径 |
| ENV 覆盖同名 ARG | 构建参数不生效 | ENV 写 `${ARG_NAME}` |
| 管道吞退出码 | 重试循环一次就退出 | 用变量接输出，保留 `$?` |
