# 【方案】Exa 能力对齐与补充（2026-10-21）

## 一、背景与结论

对 `dashboard.exa.ai` 背后的全部 Exa 产品面（Search、Contents、Answer、Agent、Monitors、Websets、Enrichment、MCP、Dashboard）做了深度调研与对抗性复核，并与本产品（data_achieve / DIH）逐项对比。

**总判断**：我们的 Exa 集成停在 2025 版 REST collector 层，相对 Exa 3.0（2026-10-19 发布）已落后。但真正的机会不是复刻 Exa 的 dashboard，而是把 Exa 能力接进我们已有的差异化资产：282 条端点目录、Postgres 记录与实体快照、调度器、信号/告警/报告三层、工作流与运行预算。

**成果指标**：MCP 工具被真实调用次数上升；对齐项差集清零。

## 二、差集矩阵

### P0（本周期）

| 能力 | 我们的现状 | 缺口 | 候选功能 |
|---|---|---|---|
| Exa 3.0 Search | 16 个 preset，覆盖 search/contents/answer/findSimilar | 缺 lite；结果上限 25；缺 snapshotAsOf/objective；已实现参数对调用方不可见 | collector 刷新：加 lite、上限提到 100、补快照参数、同步工具契约与价格簿 |
| 项目 API Keys | 模型与 `issue_key()` 已存在，无 REST/Console/MCP 接线 | 多项目隔离与日配额不可用 | 暴露 `/api/projects/{id}/api-keys`，Console 项目设置页，MCP 运行时读取密钥上下文并执行白名单与配额 |
| Exa MCP Pack | `/mcp` 共 21 个工具；Exa 只能经 `collect` 间接使用 | 没有搜索、抓取、问答、研究、监控的一等工具 | 新增 `web_search`、`web_fetch`、`answer`、`deep_research`、`monitor`；保留 `collect` 覆盖长尾端点 |

### P1（下一周期）

| 能力 | 要点 |
|---|---|
| Search Monitor | 保存检索 + 1h/6h/1d 调度 + URL/content_hash 去重 + 产出信号 + 站内/邮件通知；复用 CollectionTask 与调度器 |
| Usage & Cost | `/api/usage/summary` + Console `/usage`；按工作区/项目/provider/端点/天聚合；修价格簿（lite $4/1k、instant $4/1k、auto/fast $7/1k） |
| Contents 2.0 | `summary` 改为对象；补 extras、livecrawlTimeout、include/excludeSections、逐 URL 错误标签 |
| Exa Agent | 异步研究任务，落 runs/run_steps，effort/budget 映射成本列；deep 的 output_schema 改为可选 |
| Workspace Answer | 先检索库内 raw_records/entities 做引用回答，缺证据再调 Exa `/answer` 补外部来源 |
| Enrichment Job | 输入数据集/实体列表 + 输出 schema，逐行富集，写新数据集版本，带行状态与引用；**只做非 PII** |
| 出站 Webhook | 工作区级端点 + HMAC-SHA256 签名 + 重试 + 投递日志 |

### P2（观察）

Saved Collection（原生活集合）· findSimilar 标 legacy（官方已弃用）· 飞书机器人接搜索/问答入口。

### 明确不做

Websets UI 克隆 · AI Chat 克隆 · 独立计费与充值 · 多 provider 自动降级。

## 三、决策记录（2026-10-21 grilling 确认）

1. 目标：对外产品化为主，内部提效为副。
2. 客户：情报/数据团队 + 开发者。
3. 范围：Exa 全产品面对比；交付 REST + MCP 优先，Console 只做最小入口。
4. Exa 定位：平级 provider，默认路由 Exa，支持显式 override，不做自动降级。
5. 成本：Exa 调用不设预算上限；记录用量与成本，计费留 P4。
6. P0 三项：collector 刷新、MCP Pack、项目密钥暴露。
7. 项目密钥配额：默认硬拦（403/429），可按工作区关闭。
8. MCP 接入：项目密钥；不做 OAuth/keyless 试用；贵工具默认关，按工作区授权。
9. P1 首批：Search Monitor + Usage & Cost + Contents 2.0。
10. P1 后续：Exa Agent + Workspace Answer + Enrichment（非 PII）+ 出站 Webhook。
11. P2/不做清单见上。
12. 长任务：异步任务 + 轮询；MCP 用 start/check 两段式。
13. 变化检测产物进信号与通知，复用现有三层。
14. 分支：`feat/exa-p0`（自 main）；Agent 与 Usage 等 B3 的 runs/成本契约合并后接。
15. 节奏：按能力族拆批，每批独立迁移 → 备份 → 发布 → 真实运行验收。
16. 验收：每个能力必须有真实 provider 运行证据，不接受只跑单测。
17. 保留策略：沿用 raw_records 体系，新增来源与许可标签。
18. 成功指标：MCP 真实调用次数 + 对齐项覆盖清零。
19. 文档：本方案 + 能力图谱差集条目。
20. 分工：后端/MCP/数据模型由本会话做；Console 最小入口可交办并行会话，接口先冻结。

## 四、批次计划

### P0-A：Exa 3.0 collector 刷新

- `collectors/exa_collector.py`：新增 `lite` 类型；结果上限提到 100；补 `snapshotAsOf`、`objective`、`userIdentifier`；同步 `outputSchema` 等已有参数到公开契约。
- `collectors/endpoint_catalog.py`：新增 `exa_search_lite` preset。
- `tool_catalog/collector_specs.py`：补齐参数描述。
- `tool_catalog/fixtures/price_book_v1.json`：修正 Exa 单价。
- 验收：一次真实 Exa 调用返回记录；`test_tool_catalog.py` 通过。

### P0-B：Exa MCP Pack

- `mcp_runtime/server.py` 新增五个工具：`web_search`、`web_fetch`、`answer`、`deep_research`（start/check）、`monitor`（先只读列表，创建放 P1）。
- 工具名 provider 无关；参数支持 `provider` override。
- 贵工具默认按工作区授权开关（复用 B2 的 `tool_allowlist` 语义）。
- 验收：MCP 客户端真实调用 `web_search` 与 `web_fetch` 返回结果。

### P0-C：项目 API Keys 暴露

- REST：`POST/GET/DELETE /api/projects/{id}/api-keys`（每项目一把活跃 key；轮换先撤销再签发）。
- MCP 运行时：读取密钥上下文，执行 `tool_allowlist` 与 `daily_collect_quota`（默认硬拦）。
- Console：项目设置页最小入口（列表、签发、撤销、轮换、额度展示）——交办并行会话，接口以本文档为准。
- 验收：签发 → MCP 调用成功 → 超额度被拒 → 撤销后调用 401。

## 五、风险与开放项

- Exa 文档与 OpenAPI 在企业字段（company 的 include/excludeDomains）上互相矛盾，先按保守实现（双类均禁 domain 过滤），上线前用真实调用验证。
- `summary` 布尔写法会导致 400，P1 修。
- Websets MCP 文档页已跳回主 MCP 页，长期维护状态待确认，不作为依赖。
- 版权与 Exa ToS 边界：新增"来源与许可"标签记录，具体判定规则后续补。
- 数据保留期按工作区可配（P2 增强）。
